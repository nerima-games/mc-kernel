Make `ItemStack` canonical and immutable with only `item`, `count` in `1..max`, and resolved `components`. Zero-count stacks are replaced by empty `ItemSlot` (`undefined`) values. Component patches are resolved at decoder, recipe, and wire boundaries; `!component` removes that key, and set/remove conflicts return the typed `ItemComponentPatchConflictError` in `Either`. Patches are not retained on the stack. Kernel-owned `splitItemStack` and `mergeItemStacks` preserve resolved components and use branded `TransferQuantity` values for moves; full transfer returns an absent remainder. Downstream `mc-sim` inventory/state code must migrate zero-count sentinels to empty slots and use the canonical payload for stack moves and snapshots; `mx-gameplay` and `mx-multiplayer` must pass resolved component payloads through recipe/anvil and wire projections and remove sidecars. Those downstream repositories are outside this kernel change range. `mc-compose` must remove duplicate item metadata and sidecar normalization in favor of the kernel representation.
